# System declarations

Every system Lumen shows is described by one file, `<home>/systems/<id>.ini`,
and its games live in `<root>/games/<id>/` (e.g. `/media/games/psx/`, `/media/games/snes/`).
Lumen ships no per-system logic: adding a system means adding a file. Assets the
declaration refers to (logos, sounds) live in `<home>/assets/systems/<id>/`
(installs made before the assets folder keep them in `<home>/systems/<id>/`, which is
still read as a fallback; see assets/README.md). Data files of a declaration (the
`metadata` of `layout = stock`) stay next to it in `<home>/systems/`.

## Format

```ini
[system]
id        = psx                 ; unique, file name without .ini
name      = PlayStation         ; fallback text when there is no logo
logo      = logo.png            ; <home>/assets/systems/<id>/logo.png, white on transparent;
                                ; "psx/logo.png" (with a '/') shares another system's logo
order     = 10                  ; position of the tab

[library]
layout     = psc                ; psc: <path>/<n>/Game.ini folders | files: one file per game
                                ; | stock: the console's built-in games (below)
                                ; | apps: native homebrew programs (below)
paths      = /media/games/psx   ; ';'-separated; default: <root>/games/<id>
extensions = cue,pbp,chd,m3u    ; for layout = files (and multi-disc detection)
ports      = /media/games/psx-native   ; native ports of this system's games (below);
                                ; default: <root>/games/<id>-native

[launch]
core = pcsx_rearmed_libretro.so ; <home>/cores/<core>

[media]
kind   = disc                   ; disc | cartridge | arcade | card: the badge on the tile
cover  = 5:7                    ; the game box, width:height (or a number): the shape of this
                                ; system's tiles. Default: the box Lumen knows for the id
                                ; (nes 5:7, snes and n64 7:5, megadrive 5:7, psp 10:17 ...,
                                ; a square for an id it does not know); kept within 0.55 .. 1.5

[animation]
flat   = psx                    ; the launch's illustration, <home>/assets/launch/<flat>/ (default: the id)
sound  = launch.wav             ; optional, <home>/assets/systems/<id>/launch.wav
```

## Built-in games: `layout = stock`

The console's 20 built-in PlayStation games are on its internal, read-only game
partition (`/gaadata`), one folder per game id: `/gaadata/<id>/<BASENAME>.cue` + `.bin`
(and a cover `.png`). Their titles live in the console's SQLite database, which the
frontend cannot read (the console has no sqlite library), so a text file generated on a
computer from a copy of that database ships with the declaration:

```ini
[library]
layout     = stock
paths      = /gaadata           ; default for this layout
metadata   = psxstock.games     ; <home>/systems/<file>, default <id>.games
extensions = cue,bin            ; tried in this order for disc 1 (default cue,bin)
```

- Metadata file: UTF-8, `#` comments, one game per line:
  `id|title|publisher|year|players|basename1,basename2,...` (disc 1 first). Generated by
  `tools/make-stock-games.sh <regional.db>` (titles trimmed, the ™ and ® signs removed).
- For every line: content = `<path>/<id>/<basename1>.<ext>` with the first extension that
  exists (`.cue` preferred); a game whose disc image is missing is skipped (counted in
  the log). A game with more than one basename (multi-disc) gets a playlist written to
  `/tmp/lumen-stock/<basename1>.m3u` on every scan, listing `<path>/<id>/<basenameN>.<ext>`
  for each disc found (same extension search), and that playlist is the content, so
  RetroArch's disc control can swap discs; naming it after disc 1 keeps the save names of
  the single-disc case. With only one disc found the content stays that disc.
  Cover = `<path>/<id>/<basename1>.png`, else the first `*.png` in the folder.
  On the first scan the listing of each folder is logged once (`lumen.log`), to confirm
  the console's file names.
- Read-only: nothing is ever written under `paths` (playlists go to `/tmp`). Saves
  follow the active profile like any other game (launch request v2).
- Shown only when `show_stock_games = 1` in `settings.ini` (Settings → Library →
  Built-in games: Hidden / Visible, default Hidden). A hidden stock system is not
  loaded at all; changing the setting rescans the libraries live. Exception: when the
  stick has no games of its own (a fresh install), the built-in games are listed anyway,
  so there is always something to play; the setting is not changed.

Shipped: `psxstock.ini` ("PlayStation Classic", PlayStation logo shared with
`logo = psx/logo.png`, `pcsx_rearmed`, the PlayStation's launch (`flat = psx`), order 12 = right
after `psx`, same Original / Enhanced presets as `psx`) and `psxstock.games`.
Its `[demo] allowed = 1`: demos run as ephemeral sessions (saves in `/tmp`), so the
read-only partition is never touched, and a hidden system is never picked.

## Enhanced graphics: `[graphics]`

Optional. A system with this section appears on the settings panel's Graphics page,
where the player chooses **Original** or **Enhanced** (stored as
`graphics.<id>` in `settings.ini`, default `original`).

```ini
[graphics]
core_options_name  = PCSX-ReARMed   ; folder/file name RetroArch uses for the per-core .opt
enhanced           = pcsx_rearmed_neon_enhancement_enable=enabled, pcsx_rearmed_neon_enhancement_no_main=enabled
original           = pcsx_rearmed_neon_enhancement_enable=disabled, pcsx_rearmed_neon_enhancement_no_main=disabled
retroarch_enhanced = video_smooth=true    ; RetroArch overrides; alias: retroarch
retroarch_original = video_smooth=false
```

- Lists are **comma-separated** `key=value` pairs (`;` starts a comment, so it cannot
  separate pairs). Keys are `[A-Za-z0-9_-]`; values may not contain `,` `=` `"`.
  Invalid pairs are skipped (and logged) when the launch request is written.
- `native_720` / `native_1080` (optional) add a third level, **Native**: core options that
  render at the display's own resolution. The list for the current output is used (1080p,
  else 720p; the other one when only one is declared), with `retroarch_native` (default:
  `retroarch_enhanced`). Systems without them keep two levels; a stored `native` then
  means Enhanced. Shipped: n64 (960x720 / 1440x1080) and psp (1440x816 / 1920x1088).
- A system "has graphics" when `enhanced` or `retroarch_enhanced` is non-empty.
- `enhanced` / `original` are core options. At launch the chosen list goes into the
  launch request as `opt.*` lines, and `run.sh` merges them into
  `$LUMEN_CORE_OPT_DIR/<core_options_name>/<core_options_name>.opt`: declared keys are
  replaced, missing keys appended, every other line kept untouched. The first merge keeps
  the original file as `<file>.lumen-bak`. Choosing Original writes the `original` values
  back, so always declare both lists with the same keys. Nothing is merged when
  `LUMEN_CORE_OPT_DIR` (set by `lumen.conf`) or `core_options_name` is empty.
- `retroarch_enhanced` / `retroarch_original` are RetroArch settings. They become `ra.*`
  lines and `run.sh` writes them as `key = "value"` to the extra config handed to
  RetroArch (`$LUMEN_RA_EXTRA`), which `run_retroarch()` must pass with `--appendconfig`:
  RetroArch keeps the *first* copy of a key within one config file, so lines simply
  concatenated after its `retroarch.cfg` would be ignored.
- The merged `.opt` is the per-core file RetroArch already reads, so `LUMEN_CORE_OPT_DIR`
  must be RetroArch's real per-core config folder (its `rgui_config_directory`). No
  `core_options_path` is set. With `game_specific_options` on, a
  `<core_options_name>/<content name>.opt` overrides the preset for that game; `run.sh`
  logs a warning in `session.log` when one exists.

Shipped presets:

| system | Enhanced | Original |
|---|---|---|
| psx, psxstock | PCSX-ReARMed NEON enhancement (high internal resolution) | enhancement off |
| snes, megadrive, gba, arcade | `video_smooth=true` (bilinear filter) | `video_smooth=false` |
| n64 | 640x480 | the console's own 320x240 (both, and Native: GLideN64 on its own thread, no colour / depth buffer copies to RDRAM, no LOD or hybrid filter, frame duping) |

## Attract-mode demos: `[demo]`

Optional. When the screensaver has been showing for `attract_demo_delay` seconds and
game demos are on (settings `demo_enabled`), Lumen picks a random game of a system
that allows demos (never one of the last 4 demoed) and runs it as an **ephemeral
session**: saves and save states go to `/tmp/lumen-demo` (deleted afterwards), no
history or play time is recorded, and the demo ends after its length or when any
button is pressed (then the carousel opens with that game selected).

```ini
[demo]
allowed = 1        ; games of this system may run as attract-mode demos (default 0)
seconds = 0        ; per-system demo length override; 0 = settings "demo_seconds"
```

Shipped: `psx`, `psxstock` and `arcade` allow demos; every other system has `allowed = 0`.
A system also needs a `[launch] core` to be picked.

Unknown keys are ignored, so declarations stay forward-compatible. Every value
has a default; a minimal declaration only needs `[system] id/name`,
`[library]` and `[launch] core`.

## The launch

No 3D. A field of the game's colour wipes over the dashboard from the focused tile, the
system's machine, a flat illustration drawn after the real hardware, drops in and floats
over a line of shadow, and its medium goes into it: a cartridge into its slot, a NES Game
Pak through the front door (which then shuts), a disc under the PlayStation's lid, a
cartridge or a UMD into the back of a handheld, a coin into the arcade cabinet. A machine
with a screen lights it up, in five tones of the game's cover, and the screen grows into
the frame; one without lights its lamp and hops. Then the fade to black, with no white
flash. 2.7 s. The moment the medium seats a click plays (synthesised: a firm latch on top
loaders, a latch with a spring on front loaders, a small snap on handhelds), over the
music and independent of its volume.

The illustration is `<home>/assets/launch/<flat>/` (`[animation] flat`, default the
system's id): `launch.ini` and up to seven PNG layers of one 480 x 360 canvas (`body`,
`under`, `medium`, `over`, `lit`, `tick`, `art`), exported from the lumen-design
repository (`tools/export-launch.sh`, from `mockups/launch-flat.js`); they are not edited
by hand. Shipped: `psx`, `n64`, `snes`, `megadrive`, `nes`, `gb`, `gba`, `psp`, `arcade`.
Where a layer shows the game's art (a cartridge's label, a disc, the cabinet's marquee) it
has a hole and `art.png` is the hole's shape: at Play the game's cover is painted through
it, reduced to five flat tones of its own palette (a photographic cover clashes with a
flat drawing). Layers and cover are decoded on worker threads once the selection has
settled. Every layer is one textured quad: no models, no depth buffer.

**A system without an illustration** (homebrew apps, or a system added with a minimal
declaration) gets the generic launch on the same field: nothing is assumed about its
hardware, the game's cover is the object. It floats as a card, turns once and grows into
the frame.

**A native port** (above) runs on its system's machine, energized:
`<home>/assets/launch/<flat>-native/` (shipped: `psx-native`), an illustration with
`fx = energy` and two more layers (`aura`, `trace`). The medium goes in as always; then
light runs along the machine's edges and seams and a glow settles behind it. It hops like
any other launch, the glow swells, and its light takes the frame before the fade to black.
2.9 s instead of 2.7. The kicker reads "<system> · Native port". A system without a `-native`
illustration shows its ports as the cover, a card that switches itself on (a white edge,
two rings, the chip) and grows into the frame.

Before 0.15 the launch was drawn in 3D (jewel and keep cases, cartridges and consoles as
models). The keys of that renderer are ignored now: `[media] shape`, `aspect`, `color`,
`art`, `media_art`, and `[animation] launch`, `slot`, `idle`. A game's own disc or
cartridge picture (`<game>/disc.png`, `<name>-cart.png`) is no longer read.

## Native ports: `[library] ports`

A game recompiled to run on the console itself, with no emulator, is a program, but it is
still a game of its system: it is listed among that system's games, sorted with them by
title, and not under Homebrew. It lives in the system's ports folder, one folder per game,
in the layout of a homebrew app (below):

```
/media/games/psx-native/<name>/app.ini      Title=  Exec=  Publisher=  Year=  Players=
/media/games/psx-native/<name>/<Exec>       the program, or a shell script that starts it
/media/games/psx-native/<name>/cover.png    (or icon.png / .jpg) the game's cover
/media/games/psx-native/<name>/background.jpg, music.ogg   optional, like a game
```

- The folder is `[library] ports` (';'-separated), by default `<root>/games/<id>-native`;
  it may not exist. Systems with `layout = stock` or `apps` have none.
- A port's tile carries a "Native port" chip in its top left corner. Favourites, folders,
  history and play time work as for any game (it is identified by the path of its program).
- It launches like a homebrew app: launch request `kind=app`, `system` = the system's id,
  no core; `run.sh` starts the program from its folder (`LUMEN_APP_DIR`), RESET or OPEN
  quit it. The system's graphics levels and the CRT filter are not applied (there is no
  core to configure), and a port is never picked as an attract-mode demo.
- Its launch is its own (see "The launch"): the system's machine, energized.
- The same game can be on the stick twice, emulated (`games/psx/`) and as a port: they are
  two entries; the chip tells them apart.

## Homebrew apps: `layout = apps`

`systems/apps.ini` ("Homebrew") lists native programs for the console, one folder each:

```
/media/games/apps/<name>/app.ini      Title=  Exec=  Publisher= (or Author=)  Year=  Players=
/media/games/apps/<name>/<Exec>       the program (ARM hard-float, glibc 2.24, SDL 2.0.4 /
                                      GLES like Lumen itself); a shell script works too
/media/games/apps/<name>/icon.png     (or cover.png / .jpg) tile art
/media/games/apps/<name>/background.jpg, music.ogg   optional, like a game
```

`Exec` is relative to the folder (no `/` at the start, no `..`). Lumen writes a launch
request with `kind=app`; `run.sh` starts the program from its folder with the frontend's
`SDL_VIDEODRIVER` and `LUMEN_APP_DIR` set, its output in `logs/app.log`. A FAT32 stick
may not keep the exec bit: the program then runs from a copy in `/tmp`. RESET or OPEN
quit the app (`lumen-buttons`), which brings the dashboard back.
